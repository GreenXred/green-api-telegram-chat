# Telegram Chat Client via GREEN-API — Техническая спецификация

## 1. Цель проекта

Разработать одностраничное React-приложение с минимальным Telegram-like интерфейсом для отправки и получения текстовых сообщений через GREEN-API Telegram.

Приложение должно позволять:
- авторизоваться в GREEN-API через `idInstance` и `apiTokenInstance`;
- найти Telegram-пользователя по номеру телефона;
- открыть чат;
- загрузить историю переписки;
- отправлять текстовые сообщения;
- получать входящие текстовые сообщения без перезагрузки страницы.

## 3. Основной пользовательский сценарий

### 3.1. Авторизация

Пользователь вводит:
- `idInstance`
- `apiTokenInstance`

После нажатия кнопки «Войти» приложение проверяет доступ к GREEN-API.

При успехе пользователь переходит к экрану чата.

При ошибке показывается понятное сообщение об ошибке.

Credentials хранятся в React state и `sessionStorage`.

---

## 4. Экран чата

После авторизации пользователь видит Telegram-like интерфейс.

Основные элементы:
- header;
- кнопка logout;
- поле для ввода номера телефона;
- кнопка «Открыть чат»;
- область истории сообщений;
- поле ввода сообщения;
- кнопка отправки.

До выбора собеседника отображается empty state.

---

## 5. Открытие чата

Пользователь вводит номер телефона.

Перед отправкой номер нормализуется.

После этого вызывается GREEN-API `CheckAccount`.

Если пользователь существует:
- сохраняется `chatId`;
- сохраняется номер телефона;
- при наличии сохраняются `username` / display name;
- загружается история сообщений.

Если пользователя нет - показывается ошибка.

---

## 6. История сообщений

После успешного получения `chatId` вызывается `GetChatHistory`.

Загружаются последние сообщения выбранного чата.

На первом этапе пагинация не реализуется.

В UI показываются только текстовые сообщения.

После загрузки список автоматически прокручивается вниз.

---

## 7. Отправка сообщений

Для отправки используется `SendMessage`.

В запрос передаются:
- `chatId`;
- текст сообщения.

Поведение:
- `Enter` — отправить;
- `Shift + Enter` — новая строка;
- пустое сообщение отправить нельзя;
- на время отправки кнопка блокируется;
- после успешной отправки сообщение появляется в UI.

---

## 8. Получение входящих сообщений

Используется HTTP API GREEN-API через long polling.

Цикл:

`ReceiveNotification`
→ получение уведомления
→ обработка
→ `DeleteNotification`
→ следующий `ReceiveNotification`

Используются только текстовые входящие сообщения.

Проверяются:
- `typeWebhook === "incomingMessageReceived"`;
- `typeMessage === "textMessage"`.

Если `chatId` сообщения совпадает с текущим открытым чатом — сообщение добавляется в UI.

Уведомления из других чатов не отображаются, но также удаляются из очереди.

---

## 9. Polling

Polling выносится в отдельный hook `useNotifications`.

Требования:
- запускается после успешной авторизации;
- работает непрерывным long-polling циклом;
- корректно обрабатывает временные ошибки;
- между повторными запросами после ошибки используется задержка 1000–2000 мс;
- останавливается при logout;
- останавливается при unmount;
- активный request отменяется через `AbortController`.

---

## 10. Logout

При logout необходимо:
- остановить polling;
- очистить credentials;
- очистить текущий chat;
- очистить messages;
- очистить `sessionStorage`;
- вернуть пользователя на login screen.

## 11. Основные модели данных

```ts
type Credentials = {
  idInstance: string;
  apiTokenInstance: string;
};

type Chat = {
  chatId: string;
  phoneNumber: string;
  username?: string;
  displayName?: string;
};

type Message = {
  id: string;
  text: string;
  direction: "incoming" | "outgoing";
  timestamp: number;
};
```

---

## 12. API слой

Все обращения к GREEN-API должны находиться в отдельном модуле.

Пример структуры:

```text
src/api/
  greenApi.ts
  greenApi.types.ts
```

API client должен предоставлять методы:

```ts
getSettings()
checkAccount()
getChatHistory()
sendMessage()
receiveNotification()
deleteNotification()
```

## 13. UI / UX

Дизайн вдохновлён Telegram Web, но не является pixel-perfect копией.

Требования:
- светлый интерфейс;
- Telegram-like blue accent;
- светлый фон области переписки;
- входящие сообщения слева;
- исходящие сообщения справа;
- rounded message bubbles;
- timestamp;
- avatar placeholder;
- header чата;
- input снизу;
- заметная кнопка отправки;
- loading / error / empty states.

## 15. Автоскролл

Chat автоматически прокручивается вниз:
- после загрузки истории;
- после нового входящего сообщения;
- после нового исходящего сообщения.

---

## 16. Работа с GREEN-API instance

Telegram-аккаунт заранее авторизуется в GREEN-API Console через QR.

React-приложение не авторизует Telegram-аккаунт напрямую.

`idInstance` и `apiTokenInstance` используются только для подключения frontend-приложения к уже настроенному GREEN-API instance.

`apiTokenInstance` не должен попадать в Git.

## 18. Definition of Done

Проект считается завершённым, если работает следующий сценарий:

1. Пользователь открывает приложение.
2. Вводит `idInstance` и `apiTokenInstance`.
3. Успешно входит.
4. Вводит номер Telegram-пользователя.
5. Открывает чат.
6. Видит историю сообщений.
7. Отправляет текстовое сообщение.
8. Собеседник получает его в обычном Telegram.
9. Собеседник отвечает.
10. Ответ без перезагрузки появляется в React-приложении.
11. Повторяющиеся сообщения отсутствуют.
12. Logout корректно завершает polling и очищает сессию.
